# Dan's mod — Forge 1.21.10 (v0.79.1)

패브릭판 0.3.0과 기능 동일: 데이터팩 술식 전부 내장 + 키 시전(R 시전 / V 메뉴 / C·Z 술식 넘기기, 탑승 중 Z = 미사일 8발) + 주력 HUD + 화면 흔들림·섬광 + 개발자의 귀여운 탑승물(GeckoLib, 금 조각 "개발자 토큰3").

## 필요
- Minecraft 1.21.10 + Forge 60.x
- GeckoLib Forge `geckolib-forge-1.21.10-5.3-alpha-3.jar` (mods 폴더에 같이)
- JDK 21 (빌드는 Gradle 9.3 자동 다운로드, ForgeGradle 7)

## 빌드
```
./gradlew build        (윈도우: gradlew.bat build)
```
결과물: `build/libs/dans_mod-forge-<버전>.jar` → mods 폴더.

- `gradle.properties`의 `forge_version` 은 files.minecraftforge.net 의 1.21.10 최신값으로 바꿔도 됩니다.
- 테스트 실행: `./gradlew runClient`

## 패브릭판과 다른 점 (내부)
- 네트워크: Forge `ChannelBuilder` 페이로드 채널 (`net/JjkNet.java`)
- 등록: `DeferredRegister` + `EntityAttributeCreationEvent`
- 이벤트: EventBus 7 (`XxxEvent.BUS.addListener`, 모드 버스는 `getBus(modBus)`)
- HUD: `AddGuiOverlayLayersEvent`, 키: `RegisterKeyMappingsEvent`, 렌더러: `EntityRenderersEvent.RegisterRenderers`

## 0.44.0 — 압축 흙 → 개발자 검
- 같은 것 9개(3×3)로 다음 단계, 1개를 풀면 9개로 되돌림. 새 크리에이티브 탭 「압축 흙 → 개발자 검」
- 흙 → 단흙 → 단단흙 → 단단단흙 → 초흙 → 초초흙 → 초초초흙 → 왕흙 → 예흙 → 흣흙 → 넘흙 → 엔드흙 → 인피니티 흙 → 인피니티 → 인피니티 블럭 → 레전드 → 개발
- **개발자 검** = 개발 2 + 막대기 (세로) — 공격력 1,000,000 · 부서지지 않음 · 불에 안 탐 · 타격마다 보라 섬광 + "-999999"
- (개발 1개 = 흙 9¹⁶ = 1,853,020,188,851,841개, 검 = 흙 약 3.7천조 개)

### 게임 내 확인 방법 (직접 확인 필요 — 제작 환경에서는 Minecraft 실행 불가)
1. 아래 순서로 세로(Y축)로 쌓고 옆에 기어를 붙인다: 전동기 → 회전축 → 소기어(12T) 위로 쌓고, 소기어 **옆**에 대기어(28T)를 같은 높이·같은 축으로 설치 → 대기어 위에 회전축 → 팬.
2. 전동기 빈손 우클릭 → 스로틀 50%. 소기어가 돌고 대기어는 반대 방향으로 12/28 속도로 돈다. 팬은 대기어와 같은 속도.
3. 각 블록 빈손 우클릭으로 RPM 확인: 대기어/소기어 = 0.4286, 방향 반대.
4. 12T 옆에 20T 기어를 붙이면 맞물리지 않는다(연결 안 됨).
5. 스로틀을 올려 과부하(예: 소형 기어 열 개를 한 팬에… 또는 3개 기어 고리)면 부품이 부서진다.

## v0.80.0 — 건축물 소환기 (Structure Spawner)
개발자 전용 설계도 도구. 블록 복사가 아니라 **블록 상태·방향·블록 엔티티·기계 상태를 복원하고 기계 네트워크를 다시 구성**해서, 소환한 건축물이 그대로 작동한다.

### 사용법
- 획득: 크리에이티브 「개발자」 탭의 **건축물 소환기**. 사용 권한: OP 레벨 2 이상 또는 태그 `jjk.blueprint` (`/tag @s add jjk.blueprint`). 덮어쓰기·남의 설계도 관리: OP 레벨 3 이상 또는 태그 `jjk.blueprint.admin`. 권한 검사는 전부 서버에서 한다.
- **우클릭**: 선택한 설계도를 바라보는 블록 위에 소환 (건축물 바닥 중심을 기준점에 맞춤)
- **웅크리고 우클릭**: 관리 화면 — 고정 설계도 / 사용자 설계도 / 소환 설정 / 영역 선택·저장
  - 설계도 정보: 이름·설명·크기·블록 수·기계 수·재료 수·예상 기능(✔ 작동 ◐ 일부 ✖ 미구현)·위/앞 미리보기·필요한 재료 목록
  - 사용자 설계도: 소환·미리보기·이름 변경·설명 수정·복사·삭제 (삭제한 파일은 월드 폴더 `data/jjk_blueprints/deleted` 에 보관)
  - 소환 설정: 회전 0/90/180/270°, 좌우 반전, 기존 블록 처리(**안전 배치**(기본, 충돌 시 거부) · 빈 공간만 · 덮어쓰기(개발자 권한)), 기준점(바라보는 블록/내 위치), X·Y·Z 오프셋, 배치 전 미리보기(윤곽 + 충돌 위치 표시 + 가능 여부), 소환 취소
- **사용자 설계도 만들기**: 「영역 선택·저장」 탭에서 모드를 영역 선택으로 → 소환기로 블록 두 개를 우클릭(시작점·끝점, 선택 영역이 초록 입자로 보임) → 이름 입력 후 저장. 최대 256×256×256 (부피 400만 칸, 블록 100만 개). 저장은 월드를 바꾸지 않는다.

### 배치 엔진
1. 설계도 불러오기·검증(포맷 버전, 크기, 손상, 모르는/금지 블록, 범위 밖·중복 좌표 → 해당 항목만 빼고 경고) → 2. 서버 권한 확인 → 3. 위치 계산·회전·반전 → 4. 높이·청크 로딩·다른 작업과 겹침 검사 → 5. 충돌 검사(여러 틱) → 6. 블록 배치(이웃 갱신 없이, 붙는 블록이 떨어지지 않게) + 블록 엔티티 복원 → 7. 모양·연결 갱신 → 8. 기계 네트워크 재구성 → 9. 작동 확인(부품·네트워크·잠김) → 10. 결과 보고
- 회전·반전은 블록 상태(방향·축)뿐 아니라 **기계의 각속도·누적각·전동기 방향 부호**도 변환한다(각속도는 유사 벡터: 부호 = det × 변환된 +축의 부호). 회전 후에도 같은 기어 네트워크가 같은 기어비로 연결된다.
- 기계는 건축물 전체가 놓이고 데이터가 복원될 때까지 물리 엔진 등록을 미룬다 → 그다음 한꺼번에 포트 탐색·링크·기어비 계산.
- 틱당 처리량 제한(2048블록·8ms, 모든 작업이 나눠 씀), 액션바 진행률, 취소(놓인 데까지 마무리), 사람당 작업 1개·서버 동시 4개, 겹치는 영역 거부.
- 작업 상태(단계·커서)를 월드 폴더 `data/jjk_blueprints/jobs.nbt` 에 저장 → 배치 중 서버가 꺼져도 다음 시작 때 이어서 끝낸다.

### 안전성
- 명령 블록·구조물 블록·직소 블록 등은 저장·배치하지 않는다.
- 블록 엔티티는 **허용 목록**(타입별 허용 키)만 복원: 기계 상태(숫자 범위 검증), 컨테이너 내용물, 크래프터 잠금 칸, 배너 무늬 등. 좌표·소유자·명령·루트 테이블·엔티티 데이터는 버린다. 컨테이너 안의 명령 블록·디버그 막대·서명된 책 등은 빼고, 아이템의 엔티티/블록 엔티티 데이터 구성 요소는 지운다.
- 사용자 설계도는 월드마다 `data/jjk_blueprints/user/*.nbt` 에 저장(별도 스레드, 임시 파일 → 원자적 교체, 저장 직후 다시 읽어 검증, 이전 판 `.bak` 보관, 손상 시 백업에서 복구).

### 기계 포트 범위
현재 물리 엔진에 실제로 있는 포트는 **Mechanical** 뿐이다. Fluid·Thermal·Electrical·Control 포트는 도메인 이름만 정의돼 있어 복원할 대상이 없다(설계도 정보에 미구현으로 표시). 기계 블록이 추가되면 같은 경로(보류 → 일괄 등록 → 이웃 링크)로 복원된다.
